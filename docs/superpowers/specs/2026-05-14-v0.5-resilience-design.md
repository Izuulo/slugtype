# slugtype v0.5 — Resilience & Polish

## Purpose

Make slugtype tolerate the two real-world conditions that currently break it (terminal shrinks below the minimum mid-test; dim text invisible on terminals without 24-bit color) and bring the README in line with what the app actually does. No new features.

The TERM=dumb pre-flight guard from the original v0.5 candidate list is deferred — `cli.py:86` already catches `curses.error` cleanly enough that an extra guard isn't earning its keep right now.

## Scope

Three changes:

1. **Color fallback** — extend `init_pairs()` from two branches to three (truecolor / 16-color / 8-color). Fix the bug where `fg_dim = COLOR_BLACK` made dim text invisible on dark terminals.
2. **Resize pause/resume** — when the terminal shrinks below 60×15 during a test, pause the timer, show a "too small" overlay, resume on restore. Same overlay during the result screen (no timer to pause; purely cosmetic consistency).
3. **README updates** — drop the stale "land in v0.3" line, list all four stats, document the platform-specific `history.jsonl` location.

Explicitly out of scope:
- TERM=dumb pre-flight guard (already handled non-fatally).
- Windows path support (not in `paths.py` today).
- Any new color theme beyond the existing serika-dark.

## Architecture

No new modules. Three files change plus README:

- `src/slugtype/theme.py` — `init_pairs()` gets a three-way branch and three small per-tier helpers.
- `src/slugtype/terminal.py` — pure helper `is_too_small(rows, cols, ...)`.
- `src/slugtype/state.py` — pure helper `apply_pause_offset(state, pause_seconds)`.
- `src/slugtype/render.py` — new `draw_too_small_overlay(window)`.
- `src/slugtype/run.py` — new `_wait_until_restored(window, theme)` curses loop, plus integration in two places (mid-test resize branch, result-screen resize branch).
- `README.md` — text edits.

Pure helpers are testable without a TTY. The only un-testable code path is `_wait_until_restored`, which contains no logic beyond calling the pure helpers.

## Component design

### 1. Color fallback

Selection logic in `init_pairs()`:

```python
def init_pairs() -> Theme:
    curses.start_color()
    curses.use_default_colors()

    if curses.can_change_color() and curses.COLORS >= 16:
        _init_truecolor_pairs()
    elif curses.COLORS >= 16:
        _init_16color_pairs()
    else:
        _init_8color_pairs()

    return Theme(
        fg_correct=curses.color_pair(PAIR_FG_CORRECT),
        fg_dim=curses.color_pair(PAIR_FG_DIM),
        fg_caret=curses.color_pair(PAIR_FG_CARET),
        fg_error=curses.color_pair(PAIR_FG_ERROR),
    )
```

**Tier 1 — `_init_truecolor_pairs()`** (current behavior preserved):
- `init_color(10, 819, 816, 773)` etc., then `init_pair` against those indices.

**Tier 2 — `_init_16color_pairs()`** (new middle tier):
- `PAIR_FG_CORRECT` → `COLOR_WHITE`
- `PAIR_FG_DIM` → color index `8` (bright black / gray on every modern 16-color theme)
- `PAIR_FG_CARET` → color index `11` (bright yellow)
- `PAIR_FG_ERROR` → `COLOR_RED`

Index 8 is the standard "gray" answer: visible on dark themes and on light themes alike, because it tracks the terminal's "bright black" — never the background.

**Tier 3 — `_init_8color_pairs()`** (readable, lossy):
- `PAIR_FG_CORRECT` → `COLOR_WHITE`
- `PAIR_FG_DIM` → `COLOR_WHITE` (same as correct — accept loss of typed/untyped contrast)
- `PAIR_FG_CARET` → `COLOR_YELLOW`
- `PAIR_FG_ERROR` → `COLOR_RED`

On a true 8-color terminal we lose the typed-vs-untyped visual hierarchy. Caret position still tells you where you are; mis-typed chars are still red. The bug fixed here is *invisible text*, not low contrast.

### 2. Resize pause / resume

**Pure helper — `terminal.py`:**

```python
def is_too_small(rows: int, cols: int,
                 min_cols: int = MIN_COLS,
                 min_rows: int = MIN_ROWS) -> bool:
    """True if the terminal is below the minimum slugtype needs."""
    return cols < min_cols or rows < min_rows
```

**Pure helper — `state.py`:**

```python
def apply_pause_offset(state: TestState, pause_seconds: float) -> TestState:
    """Shift started_at forward by pause_seconds so the time spent on the
    'too small' overlay isn't counted toward the test. No-op when the test
    hasn't started (started_at is None) or has already finished."""
    if state.started_at is None or state.finished:
        return state
    return replace(state, started_at=state.started_at + pause_seconds)
```

Why shift `started_at` instead of adding a `paused_duration` field: keeps `TestState` shape unchanged, `tick()` and `stats` are untouched, no downstream callers need to learn about pause. The state simply "thinks it started later" by the pause amount.

**Curses loop — `run.py`:**

```python
def _wait_until_restored(window, theme) -> tuple[str, float]:
    """Block until the terminal is at least MIN_COLS x MIN_ROWS, or the
    user aborts via Esc / Ctrl-C.

    Returns:
      ("restored", pause_seconds) — caller resumes.
      ("aborted",  pause_seconds) — caller aborts the test/loop.
    """
    paused_at = time.monotonic()
    render.draw_too_small_overlay(window)
    window.timeout(-1)
    try:
        while True:
            keycode = window.getch()
            if keycode == -1:
                continue
            key = translate(keycode)
            if key.kind is KeyKind.RESIZE:
                rows, cols = window.getmaxyx()
                if not is_too_small(rows, cols):
                    return ("restored", time.monotonic() - paused_at)
                render.draw_too_small_overlay(window)
                continue
            if key.kind in (KeyKind.ESC, KeyKind.CTRL_C):
                return ("aborted", time.monotonic() - paused_at)
            # Any other keypress is ignored during pause.
    finally:
        window.timeout(50)
```

**Overlay renderer — `render.py`:**

```python
def draw_too_small_overlay(window, theme: Theme) -> None:
    """Paint a centered 'terminal too small' overlay. Must never raise on
    tiny window sizes (1x1 and up). Clears the window first. Uses
    theme.fg_dim so the overlay matches the existing bottom-bar style."""
```

Implementation: clear, get rows/cols, compute centered start row, then for each of three short lines call `safe_addstr` (or equivalent existing wrapper) so any out-of-bounds writes are swallowed. Lines:
- `terminal too small`
- `resize to at least 60x15`
- `esc to abort`

If the window is below the line widths, the overlay degrades gracefully — partial text is fine; nothing crashes.

**Integration — mid-test event loop (`run.py`, current line 290):**

```python
if key.kind is KeyKind.RESIZE:
    rows, cols = window.getmaxyx()
    if is_too_small(rows, cols):
        result, pause_s = _wait_until_restored(window, theme)
        if result == "aborted":
            aborted = True
            break
        state = apply_pause_offset(state, pause_s)
        last_tick += pause_s
        now = time.monotonic()
        render.draw(window, state, theme, label, now,
                    _live_wpm_for_config(state, now, config))
        continue
    render.draw(window, state, theme, label, now,
                _live_wpm_for_config(state, now, config))
    continue
```

`last_tick` is the per-second sparkline-sampling cursor (a local in the inner loop). Shifting it by the same pause amount keeps the next sample on schedule.

**Integration — result-screen loop (`run.py`, current line 340):**

The existing `decision == "redraw"` branch detects size first:

```python
if decision == "redraw":
    rows, cols = window.getmaxyx()
    if is_too_small(rows, cols):
        result, _ = _wait_until_restored(window, theme)
        if result == "aborted":
            aborted = True
            action = "exit"
            break
    render.draw_result_screen(window, state, summary, label, theme,
                              was_pb=was_pb)
    continue
```

The pause-seconds return value is discarded here — no timer to credit back.

## Edge cases

- **Shrink before `started_at` is set** (user resized before typing): `apply_pause_offset` is a no-op on `started_at=None`. Overlay shows; on restore the test resumes waiting for the first keystroke.
- **Multiple shrinks in a row**: each `KEY_RESIZE` is checked independently from the event loop. Pauses don't nest — every shrink enters `_wait_until_restored` afresh.
- **Process resized but never restored**: blocking `getch` means we sit there forever. No work is being lost; correct behavior.
- **`KEY_RESIZE` on a still-large-enough terminal** (a grow event): falls through to the existing redraw path. No pause.
- **Esc pressed during overlay**: returns `("aborted", ...)`. Mid-test, the test ends with `aborted=True` and `run_test` returns `None` (same path as Ctrl-C). Result-screen, the loop exits.
- **Terminal that loses the 16-color check between sessions**: irrelevant — `init_pairs()` re-runs on every `session()` enter.

## Testing

New tests, all pure (no TTY required):

| Module | Test | Asserts |
|---|---|---|
| `terminal.py` | `test_is_too_small_below_min_cols` | `(60, 14)` → True; `(59, 15)` → True |
| `terminal.py` | `test_is_too_small_at_min` | `(60, 15)` → False (the boundary is inclusive) |
| `terminal.py` | `test_is_too_small_above_min` | `(120, 40)` → False |
| `state.py` | `test_apply_pause_offset_shifts_started_at` | `started_at += pause_s`, other fields untouched |
| `state.py` | `test_apply_pause_offset_no_op_before_start` | `started_at=None` stays None |
| `state.py` | `test_apply_pause_offset_no_op_after_finish` | finished state unchanged |
| `theme.py` | `test_init_pairs_routes_to_truecolor` | monkeypatched curses with `can_change_color=True, COLORS=256` → truecolor helper called |
| `theme.py` | `test_init_pairs_routes_to_16color` | `can_change_color=False, COLORS=16` → 16-color helper called |
| `theme.py` | `test_init_pairs_routes_to_8color` | `COLORS=8` → 8-color helper called |
| `render.py` | `test_draw_too_small_overlay_tiny` | size 1×1 doesn't raise |
| `render.py` | `test_draw_too_small_overlay_small` | size 20×5 doesn't raise, writes *something* |
| `render.py` | `test_draw_too_small_overlay_normal` | size 50×10 writes the three expected lines |

Tests for `theme.py` use a `curses` monkeypatch that records which `init_pair`/`init_color` calls were made; we assert routing, not exact color values.

Tests for `render.py` use the existing `WindowRecorder` fake from `tests/test_render.py`.

`_wait_until_restored` is not unit-tested directly — it's a curses I/O loop whose only logic is calling pure helpers that are tested independently. This matches the existing convention (the main event loop in `run.py` is also not unit-tested).

## Manual verification

Walk these through in the worktree before declaring v0.5 user-validated:

1. `slugtype --time 60` → drag the terminal below 60×15 → overlay appears, timer freezes. Drag back to ≥60×15 → test resumes, timer continues from where it paused.
2. Same as 1, but press Esc while the overlay is showing → exits cleanly, no result screen.
3. On a 16-color terminal (`TERM=xterm-16color slugtype` or similar) → dim/upcoming text is gray and visible against a dark background.
4. On an 8-color terminal (`TERM=ansi slugtype` or `TERM=xterm-color`) → text is readable; correct and dim are the same color (acceptable degradation).
5. Finish a test → shrink the terminal on the result screen → overlay appears. Grow back → result screen redraws intact, summary numbers unchanged.
6. README renders correctly on GitHub; all four stats listed; history paths visible; no "v0.3" reference.

## Conventions to follow

- Stdlib-only runtime (no new dependencies).
- Frozen dataclasses for any state types; use `dataclasses.replace` for transitions.
- Conventional Commits with scope (e.g., `feat(state): add apply_pause_offset`, `feat(theme): add 16-color fallback tier`).
- Soft 500-line per-file limit; nothing here should push any file near that.
- Test naming `test_<function>_<scenario>`.
