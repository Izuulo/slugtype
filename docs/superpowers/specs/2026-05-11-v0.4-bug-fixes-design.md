# slugtype v0.4 — Bug Fixes

> Source PRD: `docs/2026-04-30-initial-prd.md`. This spec defers the resilience/polish slice (color fallback, resize pause/resume, TERM=dumb guard) originally proposed for v0.4 in favor of fixing six concrete UX bugs surfaced by hands-on use of v0.3a. Resilience moves to v0.5.

## 1. Goal

Make the existing UX feel correct. Three correctness fixes (escape handling, run preservation across menu cancel, result-screen stickiness), one rendering refactor (word-boundary wrapping), one behavior change (backspace crossing into imperfect previous words), and a small discoverability tweak (Ctrl-R restart + updated hint).

No new features. No new milestones from the PRD §13 list.

## 2. Scope

### In scope

- ESCDELAY fix so Esc registers immediately and menu arrow keys don't deliver bare ESC.
- Menu cancel preserves the in-progress run.
- Result screen only dismisses on explicit keys (Tab / Esc / N / Q); defensive guard around `_finalize` exceptions.
- Word-boundary wrapping in the test screen — words never split mid-character at the right edge.
- Backspace crosses into the previous word if that word had any incorrect / extra / missed chars (Monkeytype default).
- Ctrl-R as an alias for Tab (restart with same config); updated result-screen hint.
- New tests covering each fix.
- One-line amendment to PRD §5.3 to reflect the backspace rule change.

### Out of scope

- Color fallback paths (defer to v0.5).
- Resize pause/resume mid-test (defer to v0.5).
- TERM=dumb pre-flight guard (defer to v0.5).
- Quote mode, punctuation, numbers, in-app history view, saved config (later milestones).
- Surfacing persistence errors to the user (swallow silently for v0.4; revisit if it bites).

## 3. Bug catalogue & root causes

| # | Symptom | Root cause | File |
|---|---------|-----------|------|
| 1 | Esc takes a beat to open the menu | Python `curses` default `ESCDELAY` is 1000ms | `terminal.py`, `input.py:38` |
| 2 | Menu closes when arrow-keying | Same — arrow-key escape sequences not coalesced in time, bare `27` delivered, menu treats it as Esc-cancel | `run.py:148` |
| 2b | Cancelling the menu destroys the run | Esc handler always sets `restart_requested = True` | `run.py:220-225`, `run.py:281-286` |

## 4. Design

### 4.1 Escape & menu correctness

**ESCDELAY.** In `terminal.py`, before `curses.initscr()`:

```python
try:
    curses.set_escdelay(25)
except (AttributeError, curses.error):
    os.environ.setdefault("ESCDELAY", "25")
```

`set_escdelay` exists in Python ≥3.9; the env-var fallback covers older builds and any platform where the function raises. Must be set *before* `initscr()` because ncurses reads the env var at init.

**Menu cancel preserves the run.** Add `Config.__eq__` — the dataclass already gets it from `@dataclass(frozen=True)`. Then in `run.py`:

```python
# mid-test Esc handler (line ~220)
if key.kind is KeyKind.ESC:
    new_config = _open_menu(window, theme, config)
    if new_config is not None and new_config != config:
        config = new_config
        restart_requested = True
        break
    # cancelled OR no change → resume the in-progress run
    render.draw(window, state, theme, label, now,
                _live_wpm_for_config(state, now, config))
    continue
```

Same shape on the result-screen Esc handler (line ~281): on cancel/identical, redraw the result screen and loop back to blocking input rather than restarting.

### 4.2 Result-screen stickiness

**Explicit dispatch.** Replace the post-result-screen loop:

```python
window.timeout(-1)
while True:
    keycode = window.getch()
    if keycode == -1:
        continue
    key = translate(keycode)
    if key.kind is KeyKind.RESIZE:
        render.draw_result_screen(...)
        continue
    if key.kind is KeyKind.TAB or key.kind is KeyKind.CTRL_R:
        action = "restart"
        break
    if key.kind is KeyKind.ESC or (key.kind is KeyKind.CHAR and key.char == "n"):
        new_config = _open_menu(window, theme, config)
        if new_config is not None and new_config != config:
            config = new_config
        action = "restart"
        break
    if key.kind is KeyKind.CHAR and key.char == "q":
        action = "exit"
        break
    if key.kind is KeyKind.CTRL_C:
        aborted = True
        action = "exit"
        break
    # anything else: ignore, keep waiting
```

The drain loop before this stays — defense in depth against keys queued during the last tick.

**Defensive `_finalize`.** Wrap the call in `run_test`:

```python
try:
    was_pb = _finalize(
        state, summary, config,
        datetime.now(timezone.utc),
        paths.history_path(),
    )
except Exception:
    was_pb = False
render.draw_result_screen(window, state, summary, label, theme, was_pb=was_pb)
```

Broad `except Exception` is intentional: any persistence failure (disk full, permission, partial-write) must not prevent the user from seeing their result. `_finalize` internals (`history.append`, `history.load_all`) remain unchanged; the catch is at the call site.

### 4.3 Word-boundary wrapping

**New segment structure.** `_build_segments` becomes `_build_word_blocks` and returns:

```python
WordBlock = tuple[list[tuple[str, int]], int]   # (segments, total_length)
# return: (list[WordBlock], caret_block_idx)
```

Each block contains the colored runs for one word *including its trailing space*. The trailing space is part of the block so it can't be orphaned to a new line.

**Layout.** `_layout_lines(blocks, caret_block_idx, inner_cols) -> (lines, caret_line)`:

```python
for block_idx, (segments, length) in enumerate(blocks):
    if line_lens[-1] > 0 and line_lens[-1] + length > inner_cols:
        # wrap the WHOLE block to the next line
        lines.append([])
        line_lens.append(0)
    if block_idx == caret_block_idx:
        caret_line = len(lines) - 1
    for seg in segments:
        lines[-1].append(seg)
    line_lens[-1] += length
```

**Pathological case: block longer than `inner_cols`.** Falls back to per-segment wrapping for that block alone (the existing logic, scoped). Never triggers for english-200/english-1k words at terminal widths ≥60 cols, but the guard means we don't drop characters silently for the extras-spam case.

**Renderer untouched.** The outer render loop in `draw_word_stream` continues to iterate `lines[viewport_top : viewport_top + 3]` and write segments left-to-right at `x=2, y=2+i`. Viewport math is unchanged.

### 4.4 Backspace crosses into imperfect previous words

**Predicate in `state.py`:**

```python
def _word_was_perfect(word: WordEntry) -> bool:
    if len(word.typed) != len(word.expected):
        return False  # missed chars
    return all(tc.category == "correct" for tc in word.typed)
```

**Updated `_apply_backspace`:**

```python
def _apply_backspace(state: TestState) -> TestState:
    current = state.words[state.current_index]
    if len(current.typed) == 0:
        if state.current_index == 0:
            return state
        prev = state.words[state.current_index - 1]
        if _word_was_perfect(prev):
            return state
        # Cross into the imperfect previous word; caret lands at end of its typed buffer.
        unsubmitted = WordEntry(
            expected=prev.expected, typed=prev.typed, submitted=False,
        )
        new_words = (
            state.words[: state.current_index - 1]
            + (unsubmitted,)
            + state.words[state.current_index :]
        )
        return replace(state, words=new_words, current_index=state.current_index - 1)
    # in-word backspace: unchanged
    new_word = WordEntry(
        expected=current.expected, typed=current.typed[:-1], submitted=current.submitted,
    )
    new_words = state.words[: state.current_index] + (new_word,) + state.words[state.current_index + 1 :]
    return replace(state, words=new_words)
```

The crossed-back word is restored to `submitted=False`, which `_build_word_blocks` treats as the current word — caret renders inside it.

**PRD amendment.** Replace the §5.3 backspace bullet with:

> **Backspace:** delete one character within the current word. If the current word's buffer is empty, backspace crosses into the previous word **only if that word had any incorrect, extra, or missed characters** (Monkeytype default). Fully-correct previous words stay locked.

### 4.5 Quick reset keybind

- `input.py`: add `CTRL_R = auto()` to `KeyKind`. In `translate`, map `keycode == 18` to `Key(kind=KeyKind.CTRL_R)`. Place the check above the printable-char fallback so it's not interpreted as a CHAR.
- `run.py`: in both the mid-test and result-screen loops, branch on `key.kind in (KeyKind.TAB, KeyKind.CTRL_R)` instead of just `KeyKind.TAB`.
- `render.py`: result-screen hint becomes `"tab/ctrl-r restart · esc menu · n new · q quit"`.

2. Inside menu, ↑/↓/←/→ → menu stays open, selection moves.
3. Cancel menu (Esc) → test resumes; timer didn't reset; previously-typed words still visible.
4. Finish a test, mash random keys (`a`, `s`, `d`, `f`) → result screen stays.

6. From result screen: `tab` restarts; `ctrl-r` restarts; `esc` opens menu; `n` opens menu.
7. Type "wrong" + space (correctly-typed: 5 correct chars); now on next word; backspace → caret stays.

## 6. Risks & open questions

- **ESCDELAY behavior on macOS Terminal.app vs iTerm2 vs tmux.** Setting to 25ms works reliably in mainstream curses apps (vim, fzf, less use ~25-50ms). If a specific terminal still drops Esc on us we'll add per-terminal handling, but it's not expected.
- **Word-block refactor impacts the viewport-scroll algorithm.** Caret line tracking moves from segment-index to block-index. The viewport math (`viewport_top = max(0, caret_line - 1)`) stays the same since it operates on line indices, not segment indices.
- **Backspace UX with multiple imperfect words behind.** Each backspace can cross at most one word boundary per keypress. Crossing chains naturally (each press deletes one char, then once the buffer is empty the next press considers crossing again).
- **Edge case: `current_index > 0` but `state.words[current_index]` has `typed=()` and is the *last* word in words-mode.** Crossing back un-submits the previous word; user can then re-submit it. The test isn't `finished` yet (only set on space-on-last-word), so this is consistent.
