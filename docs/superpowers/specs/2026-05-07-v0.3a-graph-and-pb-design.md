# slugtype v0.3a — Result Sparkline, History Persistence, PB Badge

> Source PRD: `docs/2026-04-30-initial-prd.md`. The PRD groups four features under v0.3 (sparkline, `history.jsonl`, history view, PB badge). This spec covers three of them — **everything except the scrollable history view**, which is deferred to its own spec (v0.3b). The history view is a separate modal screen with its own keynav UX and benefits from a dedicated design pass.

## 1. Goal

Bring the result screen to PRD §5.4 fidelity (minus the two-series overlay) and start writing test results to disk so personal bests can be detected:

1. Render a per-second WPM sparkline on the end-of-test result screen.
2. Persist every completed test as a JSONL line on disk.
3. Detect when the just-finished run is a personal best for its config and surface a small `pb` badge on the result screen.

Everything else stays as it is.

## 2. Scope

### In scope (v0.3a)

- New module `paths.py` — single-function platform-aware data directory resolver.
- New module `history.py` — JSONL append, load, PB query, PB validity check.
- New module `sparkline.py` — pure glyph computation for the result-screen chart.
- `render.py` — extended `draw_result_screen` to draw the chart and a `pb` badge; small-terminal fallback that omits the chart.
- `run.py` — wires history append + PB query into the post-test path; passes `was_pb` and the samples through to the renderer.
- Tests for all of the above (TTY-free; recorder-fake for render assertions).

### Out of scope

- **History view (v0.3b).** Scrollable table screen, replay-graph rendering for old tests, menu entry to open the view.
- **Two-series sparkline.** Per-second net WPM is not currently tracked; v0.3a renders only the raw series. Adding a net series is a self-contained future change (new `TestState` field, new tick-side computation, second render path).
- Punctuation, numbers, quote mode, words mode polish — all v1.0 milestone items.
- Any history-file maintenance (rotation, compaction, migration). Linear scan over `history.jsonl` is fine until tens of thousands of entries.

## 3. Architecture

### 3.1 New modules

#### `src/slugtype/paths.py`

Platform-aware data-directory resolver. Single public function:

```python
def data_dir() -> pathlib.Path: ...
```

Resolution order:

- macOS (`sys.platform == "darwin"`): `~/Library/Application Support/slugtype/`
- Linux: `$XDG_DATA_HOME/slugtype/` if set, else `~/.local/share/slugtype/`

Side effect: ensures the directory exists via `mkdir(parents=True, exist_ok=True)`. If creation fails, returns the path anyway — callers handle write errors.

Convenience accessor `history_path() -> Path` returns `data_dir() / "history.jsonl"`.

#### `src/slugtype/history.py`

Persistence and PB queries. Public surface:

```python
@dataclass(frozen=True)
class Record:
    ts: str                # ISO 8601 UTC, e.g. "2026-05-07T19:14:02Z"
    wpm: float
    raw: float
    acc: float
    consistency: float
    mode: str              # "time" | "words"
    length: int            # duration_s for time mode, word_count for words mode
    language: str
    punctuation: bool      # always False in v0.3a; reserved for v1.0
    numbers: bool          # always False in v0.3a; reserved for v1.0
    chars: dict            # {"correct": int, "incorrect": int, "extra": int, "missed": int}
    duration_s: float
    samples: tuple[float, ...]   # per-second raw WPM

def record_from_state(state, summary, config, ts: datetime) -> Record: ...
def append(record: Record, path: Path) -> None: ...   # best-effort; swallows OSError
def load_all(path: Path) -> list[Record]: ...         # returns [] on missing/empty
def pb_for(records: list[Record], key: tuple) -> Optional[Record]: ...
def pb_qualifies(state, summary) -> bool: ...
def config_key(record_or_config) -> tuple: ...        # (mode, length, language, punctuation, numbers)
```

PB validity rules (per PRD §5.5, also enforced by `pb_qualifies`):

- Test ran for ≥ 1 second.
- Accuracy ≥ 75%.
- The run finished naturally (Tab-aborts and Ctrl-C never reach the post-test path, so no extra check is needed in code; this is a documentation note).

`pb_for` filters `records` by `key` and returns the record with the highest `wpm`, or `None` if no records match. The filter implicitly enforces accuracy ≥ 75% by requiring the candidate's `acc` field to be ≥ 75; this avoids ever crowning a low-accuracy run as PB even if one slipped into the file.

`load_all` is line-by-line tolerant: malformed JSON lines are skipped (logged via `_dbg` if `SLUGTYPE_DEBUG` is set), missing fields fall back to safe defaults (`punctuation=False`, `numbers=False`, `samples=()`), records lacking a `wpm` field are skipped during PB scan.

#### `src/slugtype/sparkline.py`

Pure glyph computation, no curses. Public surface:

```python
def chart_lines(samples: Sequence[float], width: int, height: int) -> list[str]: ...
```

- `samples`: per-second values (typically `state.raw_per_second`).
- `width`: total chart width in columns including axis labels.
- `height`: number of plot rows (excludes the axis row and X-axis tick row).
- Returns a list of strings — one per output row, top to bottom — each exactly `width` chars wide.
- The first column on each plot row is the Y-axis label (right-aligned in a 3-char gutter); column 4 is the `┤` axis edge; columns 5+ are the plotted line.
- The bottom row is the X-axis: `┼` followed by `─`s with X-tick labels rendered on the line below if there's room, else inline using the same row.

Returns `[]` when `len(samples) < 2`, when `width < 10`, or when `height < 2`. The renderer uses an empty return as the signal to omit the chart entirely.

Glyphs (Unicode box-drawing): `╭ ╮ ╯ ╰ ─ │ ┤ ┼ ╱ ╲`. The line is drawn by computing a quantized row index per sample and joining adjacent points with sloped/horizontal characters.

Y-axis range: `0` to `ceil(max(samples) / 15) * 15`. Labels at quarters (0, q, 2q, 3q, top). When max sample < 15, top is set to 15 so the chart always has a sensible scale.

X-axis: 5 evenly-spaced ticks. Labels formatted as integer seconds with `s` suffix (`0s`, `15s`, `30s`, `45s`, `60s`).

### 3.2 Modified modules

#### `src/slugtype/render.py`

`draw_result_screen` gains:

- New parameter `was_pb: bool = False`.
- When `was_pb` is true, the headline `wpm` cell renders the value followed by a single space and `pb` in `theme.fg_caret`. Implementation: when computing `col_center` for the wpm cell, render the value at the existing position, then `addstr` the `pb` suffix in the same row.
- A new private helper `_draw_sparkline(window, samples, x, y, width, height, theme)` invokes `sparkline.chart_lines` and writes each returned row with `theme.fg_correct` for plot characters and `theme.fg_dim` for axis chars. Axis chars are detected by glyph (`┤ ┼ ─` and digit/letter axis labels render dim).
- Vertical layout: chart is inserted between the headline row block and the sub-row block. Chart height: 5 plot rows + 1 X-axis row + 1 X-tick label row = **7 rows total**. Chart width: `min(60, cols - 4)`.
- Small-terminal fallback: when `rows < 18`, skip the chart entirely (no `_draw_sparkline` call) and keep the existing layout. The 60×15 PRD minimum is preserved.

The hint row, sub-stats row, and headline row are unchanged.

#### `src/slugtype/run.py`

After a test completes naturally (the existing `summary = stats.summary(state)` line):

```python
if history.pb_qualifies(state, summary):
    record = history.record_from_state(state, summary, config, datetime.now(timezone.utc))
    # Compare against existing records *before* writing, so the new run isn't
    # its own baseline.
    prior_records = history.load_all(paths.history_path())
    key = history.config_key(record)
    prev_pb = history.pb_for(prior_records, key)
    was_pb = prev_pb is None or record.wpm > prev_pb.wpm
    history.append(record, paths.history_path())
else:
    was_pb = False

render.draw_result_screen(window, state, summary, label, theme, was_pb=was_pb)
```

(Non-qualifying runs — sub-1s, sub-75% acc — are not written to disk and never PB.)

`paths.history_path()` is called inside `run.py` rather than at module import so tests can monkeypatch the resolver.

### 3.3 Data flow

```
test finishes naturally
    │
    ├─ stats.summary(state) ──────────────────────────────► Summary
    │
    ├─ history.pb_qualifies(state, summary)
    │     │
    │     yes │
    │     ▼
    │   history.record_from_state(state, summary, config, now)
    │   history.load_all(history_path)              ◄── before append, so the new
    │   history.pb_for(prior_records, key)              record isn't its own baseline
    │   was_pb = prev_pb is None or record.wpm > prev_pb.wpm
    │   history.append(record, history_path)        ◄── best-effort, swallows OSError
    │     │
    │     no │
    │     ▼
    │   was_pb = False
    │
    ▼
render.draw_result_screen(... was_pb, samples=state.raw_per_second)
```

## 4. JSONL schema

One JSON object per line, written in append mode. Field order is not significant; the example is for readability.

```json
{"ts":"2026-05-07T19:14:02Z","wpm":87.3,"raw":91.2,"acc":96.4,"consistency":74.2,
 "mode":"time","length":60,"language":"english-1k",
 "punctuation":false,"numbers":false,
 "chars":{"correct":438,"incorrect":18,"extra":6,"missed":0},
 "duration_s":60.0,"samples":[42.0,51.0,60.0,58.0]}
```

Field notes:

- `ts` — UTC ISO 8601 with `Z` suffix; produced by `datetime.now(timezone.utc).strftime("%Y-%m-%dT%H:%M:%SZ")`.
- `length` — `duration_s` for time mode, `word_count` for words mode. PRD §5.5 makes this part of the PB key.
- `punctuation`, `numbers` — always `false` in v0.3a. Written so PB keys remain stable when those features land in v1.0; old records will already match new tests that have these features turned off.
- `chars.missed` — currently always 0 in slugtype's category set (v0.3a tracks correct/incorrect/extra). Written for forward compatibility with any future "missed" tracking.
- `samples` — copy of `state.raw_per_second`. Required for v0.3b's per-test replay graph; cheap to write now even though v0.3a doesn't read it back.

## 5. PB key

```python
config_key(r) = (r.mode, r.length, r.language, r.punctuation, r.numbers)
```

Tuple equality. Two runs with identical keys compete; runs with different keys do not.

A run is PB when:

1. `pb_qualifies(state, summary)` returns True (≥ 1s, ≥ 75% acc).
2. `pb_for(prior_records_with_same_key)` returns `None` (no prior PB), OR `summary.wpm > prev_pb.wpm` (strict greater — ties don't beat the existing PB).

## 6. Sparkline rendering

ASCII reference (mock from PRD §5.4, redrawn for v0.3a single-series):

```
   60 ┤                          ╭─╮
   45 ┤        ╭─╮      ╭───╮   ╱   ╲   ╭──
   30 ┤   ╭───╯   ╲────╯     ╲─╯     ╲─╯
   15 ┤  ╱
    0 ┼──────────────────────────────────────
      0s          15s          30s          45s          60s
```

- 5 plot rows, 1 baseline (`┼─`) row, 1 X-tick label row → 7 rows.
- Width: `min(60, cols - 4)`. Chart is horizontally centered when narrower than `cols - 4`.
- Plot color: `theme.fg_correct`. Axis (Y labels, `┤`, `┼`, `─` baseline, X labels): `theme.fg_dim`.
- Y range: `0` to `ceil(max(samples) / 15) * 15`, with a floor of 15.
- Sample-to-column mapping: `col = round(i * (chart_width - 1) / max(1, len(samples) - 1))`. Adjacent samples connect with `─` (flat), `╭`, `╮`, `╯`, `╰` (corners), or `╱`, `╲` (steep transitions).
- When two consecutive samples land in the same row and adjacent columns, render `─`.
- When fewer than 2 samples, return `[]`; renderer omits the chart.

## 7. Result-screen layout

Final mock for a 24-row terminal, 80-col wide:

```
 slugtype — result                                            60s · english-1k

       wpm        acc        raw        consistency
       87 pb      96.4%      91         74.2%

   60 ┤                          ╭─╮
   45 ┤        ╭─╮      ╭───╮   ╱   ╲   ╭──
   30 ┤   ╭───╯   ╲────╯     ╲─╯     ╲─╯
   15 ┤  ╱
    0 ┼──────────────────────────────────────
      0s          15s          30s          45s          60s

   characters         time
   438 / 18 / 6       60.0s

                  tab restart · esc menu · any other key exits
```

Vertical slot order, top to bottom:

1. Top bar (1 row)
2. Headline labels + values (3 rows: label, blank, value)
3. Chart (7 rows when `rows >= 18`; omitted otherwise)
4. Sub-stats labels + values (2 rows)
5. Hint (1 row, anchored to `rows - 2`)

The chart insert pushes the sub-stats and hint down. When the chart is omitted (small terminal), the existing v0.2 layout is preserved exactly.

## 8. Error handling

| Failure | Response |
|---|---|
| `paths.data_dir()` cannot create directory | Return path anyway; downstream `append` swallows. |
| `history.append` write fails | Swallow `OSError`; log via `_dbg`; result screen still renders. |
| `history.load_all` file missing | Return `[]`. |
| `history.load_all` malformed line | Skip line; log via `_dbg`; continue with remainder. |
| `history.load_all` record missing `wpm` | Skipped during `pb_for` scan. |
| Schema drift — record missing `punctuation`/`numbers`/`samples` | Defaults: `False`, `False`, `()`. |
| Sample list of length 0 or 1 on result screen | Chart omitted (no plot, no axis row). |
| Terminal `rows < 18` on result screen | Chart omitted; rest of result screen renders normally. |

The principle: a finished test never fails to display because of a persistence or rendering edge case. The user's last action — typing — is honored.

## 9. Testing

All new tests are TTY-free. Render tests use the existing `RecorderWindow` fake from `tests/conftest.py`.

### `tests/test_paths.py`

- `test_data_dir_macos` — monkeypatch `sys.platform` to `"darwin"`, assert path ends with `Library/Application Support/slugtype`.
- `test_data_dir_linux_with_xdg` — monkeypatch `XDG_DATA_HOME` to a `tmp_path`, assert path ends with `slugtype` under that root.
- `test_data_dir_linux_fallback` — clear `XDG_DATA_HOME`, assert path ends with `.local/share/slugtype`.
- `test_data_dir_creates_directory` — assert `data_dir()` is a directory after the call.

### `tests/test_history.py`

- `test_record_from_state_roundtrip` — feed a fixtured finished `TestState` + summary + config, assert all `Record` fields populated correctly.
- `test_append_creates_file` — `append` to a non-existent path, then `load_all` returns one record matching what was written.
- `test_append_swallows_oserror` — point `append` at an unwritable path, assert no exception raised.
- `test_load_all_missing_file` — returns `[]`.
- `test_load_all_skips_malformed` — fixture file with one good line, one garbage line; `load_all` returns one record.
- `test_load_all_defaults_missing_fields` — record JSON without `punctuation`/`numbers` loads with `False` defaults.
- `test_pb_for_filters_by_key` — three records, two share a key; `pb_for` returns the higher-wpm of the two.
- `test_pb_for_no_match` — `pb_for` returns `None` when no records match the key.
- `test_pb_qualifies` — three sub-cases: < 1s rejected, < 75% acc rejected, 60s/96% accepted.
- `test_config_key_shape` — key tuple has the expected 5 fields in the expected order.

### `tests/test_sparkline.py`

- `test_empty_returns_empty_list`.
- `test_single_sample_returns_empty_list`.
- `test_two_samples_known_fixture` — assert exact row strings for `[10, 50]`, width=20, height=5.
- `test_realistic_60_samples` — fixture with values rising and falling; assert returned list length matches `height + 2` (plot + axis + tick row), each row is exactly `width` chars, peak sample is plotted in the top plot row.
- `test_y_axis_floor_15` — small samples (e.g. all < 15); top label is `15`, not the sample max.
- `test_y_axis_quarters` — samples reaching 80; top label `90` (next 15-multiple), middle labels at `0, 22, 45, 67, 90` rounded to integers.

### `tests/test_render.py` (extend)

- `test_result_screen_with_pb_shows_badge` — `was_pb=True`, recorder shows "pb" near the wpm value.
- `test_result_screen_without_pb_omits_badge` — `was_pb=False`, recorder has no "pb" string.
- `test_result_screen_small_terminal_omits_chart` — window with rows=15; recorder has no chart glyphs (`┤`, `┼`).
- `test_result_screen_full_terminal_includes_chart` — window with rows=24; recorder includes chart glyphs.

### `tests/test_run.py` (new — light integration)

- `test_completed_test_writes_history` — synthesize a completed `TestState`, run the post-test code path with `paths.history_path` monkeypatched to `tmp_path / "history.jsonl"`; assert one line written.
- `test_second_run_is_pb_when_faster` — write a slow run, then a faster run with the same config; assert `was_pb=True` for the second.
- `test_second_run_not_pb_when_slower` — write a fast run, then a slower run; `was_pb=False`.
- `test_tied_wpm_not_pb` — second run has identical wpm to first; `was_pb=False` (strict greater is enforced in `run.py`).
- `test_failed_qualification_does_not_write` — run with 50% accuracy is not appended.

These integration tests exercise `run.py` only at the post-test path level; they do not spin up the curses event loop. The cleanest factoring is to extract the post-test "decide PB and persist" block into a helper (e.g. `_finalize(state, summary, config, now)` returning `was_pb: bool`) and call it directly from tests.

### Coverage

- `paths.py`, `history.py`, `sparkline.py`: 100%.
- `render.py` extensions: covered by render tests.
- `run.py` post-test block: covered by `test_run.py` integration.

## 11. Acceptance for v0.3a

- A 60-second english-1k test runs to completion and the result screen shows a sparkline of per-second WPM.
- After the first qualifying run, `history.jsonl` exists at the platform-correct path with one JSON line.
- Running a second qualifying test that beats the first shows `pb` next to the wpm value on the result screen.
- A test under 1 second or under 75% accuracy is not written to history and is never marked PB.
- A test on a 60×15 terminal still completes and shows the result screen, with the sparkline omitted gracefully.
- A history-file write failure (e.g. read-only filesystem) does not prevent the result screen from rendering.
- `pytest` passes; the four new test files plus the extensions to `test_render.py` exercise every new public function.

## 12. Out-of-scope reminders for v0.3b

- Scrollable history table screen with date / wpm / acc / mode / length columns.
- Per-test replay: open an old record and re-render its sparkline on a result-screen-shaped view.
- Menu entry "history" that opens the view.
- Up/down navigation, enter-to-replay, esc-to-close.

These will read `history.jsonl` via the same `history.load_all` defined in this spec.
