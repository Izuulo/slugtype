## What v0.4 fixed

Six concrete bugs the user surfaced from hands-on use:

1. **ESCDELAY** — Default `curses` escape delay was 1000ms, making Esc lag and causing arrow keys in the menu to deliver bare ESC (which closed the menu). Fixed in `terminal.py` by setting `ESCDELAY=25` before `initscr()`.
2. **Menu cancel destroyed the run** — Esc-cancel previously triggered a restart. Now `_menu_cancel_should_restart` returns False on `None` or unchanged config; the run resumes.
3. **Result screen dismissed on any keystroke** — Replaced "any other key exits" with explicit dispatch via `_result_screen_dispatch`. Only `tab/ctrl-r/esc/n/q/ctrl-c` trigger transitions; everything else is ignored.
4. **`_finalize` could suppress the result screen** — Wrapped in `_safe_finalize` so persistence errors (disk full, permission) no longer crash the post-test flow. PB badge is lost; screen still renders.
5. **Words split mid-character at the right edge** — Refactored `render.py`: segments are now grouped into per-word blocks; whole blocks wrap as a unit. Pathological blocks longer than `inner_cols` fall back to per-segment wrapping.
6. **Backspace couldn't cross into previous words** — `_apply_backspace` now crosses into the previous word if and only if `_word_was_perfect(prev)` is False (Monkeytype default). PRD §5.3 amended.

Plus:
- **Ctrl-R** added to `KeyKind`, aliased to Tab in both the mid-test loop and the result-screen dispatch.
- **Hint string** updated from "tab restart · esc menu · any other key exits" to "tab/ctrl-r restart · esc menu · n new · q quit".

## Pure helpers introduced (for future test reference)

All in `src/slugtype/`:

| Helper | Module | Purpose |
|---|---|---|
| `_configure_escape_delay()` | `terminal.py` | Sets `ESCDELAY=25` env var pre-`initscr` |
| `_word_was_perfect(word)` | `state.py` | Predicate: typed length == expected AND all chars correct |
| `_build_word_blocks(state, theme)` | `render.py` | Groups segments per word; returns `(blocks, caret_block_idx)` |
| `_result_screen_dispatch(key)` | `run.py` | Maps key → "restart" / "menu" / "exit" / "abort" / "redraw" / "ignore" |
| `_menu_cancel_should_restart(old, new)` | `run.py` | True only if user picked a different config |
| `_safe_finalize(...)` | `run.py` | Wraps `_finalize` in `try/except Exception` |

Each is unit-tested independently (no curses required).

## Open follow-ups

### Non-blocking polish (raised in v0.4 code review)

- `_layout_lines` uses a `line_lens: list[int]` accumulator when only `line_lens[-1]` is ever read. A scalar `current_line_len: int` reset per line would be clearer.
- `_build_word_blocks` return type `tuple[list[tuple[list[tuple[str, int]], int]], int]` would read better with a named alias: `Block = tuple[list[tuple[str, int]], int]`.
- ESCDELAY fix uses env var only. The spec called for env var + `curses.set_escdelay(25)` as belt-and-suspenders. Functionally equivalent on Python 3.9+, but the doubled approach is more future-proof.
- Legacy test `test_backspace_does_not_cross_word_boundary` (in `tests/test_state.py`) still passes but its name describes the old universal rule. The new `test_backspace_does_not_cross_perfect_previous_word` covers the same case under a correctly-scoped name. Consider renaming or removing the legacy one.

## Manual verification the user should run

Before declaring v0.4 user-validated, walk through these in the worktree:

1. `slugtype --time 30` → press Esc → menu opens instantly (no 1s lag).
2. Inside menu, ↑/↓/←/→ → menu stays open while selection moves.
3. Cancel menu (Esc) → test resumes; timer and previously-typed words intact.
4. Finish a test, mash random letters (`a`, `s`, `d`, `f`) → result screen sticks.
5. From result screen: `q` exits; `tab` and `ctrl-r` both restart; `esc` and `n` open menu.
6. Type "the" exactly + space + backspace → caret stays on next word.
7. Type "thx" (one wrong) + space + backspace → caret jumps back into "thx".
8. Type until current word approaches the right edge → whole word wraps to next line, no mid-character split.

If any fail, treat as a v0.4 regression and re-open the bug.

## Conventions worth knowing

- **Stdlib-only runtime.** No runtime deps beyond Python stdlib. `pytest` is dev-only.
- **Pure logic vs. curses I/O.** `state.py`, `stats.py`, `words.py`, `history.py`, `sparkline.py`, `paths.py` are all pure and unit-tested without a TTY. `render.py` uses a `WindowRecorder` fake (see `tests/test_render.py`) for behavior tests. `run.py` extracts pure helpers (the dispatchers + `_safe_finalize`) so the curses event loop is the only un-testable part.
- **Frozen dataclasses.** `TestState`, `WordEntry`, `TypedChar`, `Config`, `Summary` are all frozen — use `dataclasses.replace` for transitions.
- **Module-size budget.** Soft 500-line limit per file. Current largest is `run.py` at 375.
- **Test naming.** `test_<function>_<scenario>` snake-case.
- **Commit messages.** Conventional Commits prefixes (`feat:`, `fix:`, `refactor:`, `docs:`, `test:`); scope in parens (`feat(state):`); imperative present tense in the subject. Co-Authored-By trailer added by the harness automatically.
